# 运行检查清单

## 首次运行与交付

1. 在部署机确认 Node.js 20 以上、本机 Chrome 可用，启动账号可以打开可见浏览器窗口，并有权写入项目目录下的档案、任务和临时素材目录。
2. 按 [本地运行与验证](../development/local-verification.md) 安装锁定依赖并执行测试。确认监听地址和端口符合接入方式。仅本机调用时可绑定环回地址。远程接入需要环境提供网络隔离或调用方鉴权。服务自身能读取运行账号可访问的本地素材并请求远程 URL。
3. 按 [运行依赖与任务数据](runtime-and-data.md) 设置账号、团队和风格。检查运行机能够访问 Dramart、测试素材和上传地址，调用方能够访问上游媒体地址。
4. 启动 `npm run start:node-task`。确认输出监听地址，通过 `GET /health` 检查 HTTP 响应。首次认证时检查 Chrome 的登录页面和服务日志，核对实际团队。
5. 在测试团队按 [媒体生成索引](../media-generation/index.md) 分别提交启用的任务类型。保存任务 ID，等到 `result.status: success`，检查图片数组或视频地址，再访问 `/api/files/<task_id>` 返回的实际媒体。对于生图多张输出，逐张检查结果数组。项目视频还应检查正确的项目、集和分镜。
6. 交付时记录实际 Node/Chrome 版本、监听地址、登录方式、团队、风格、工作目录和测试记录。账号密码由环境指定的方式交接。

## 故障定位

| 现象 | 核对步骤 |
| --- | --- |
| 进程退出或健康检查连不上 | 看 `Seedance task server startup failed` 和监听日志。检查端口、工作副本权限、运行 JSON 的文件名与 ID、排队任务请求文件。恢复在监听前完成。 |
| 健康成功，任务一直处理中 | 先在 `requests`、`running`、`results` 按任务 ID 查找。合法但未知的任务 ID 也会返回 `processing`。检查是否打到同一工作副本，以及是否为重启遗留生图。 |
| 启动 Chrome 或连接失败 | 看 `[chrome.open]`、`[browser.ready]`、`[image-session.ready_error]`。检查 Chrome 路径、当前用户对档案的权限、浏览器窗口和调试端点。 |
| 日志反复 `[auth.waiting]` | 核对 Chrome 中登录状态、账号配置 JSON、团队和 Dramart 项目列表访问。没有完整凭据时，在该 Chrome 窗口手动登录。 |
| 待命页掉线后共享 Canvas 未重开 | 核对项目列表是否跳到登录页，以及账号配置是否可用于自动登录。检查 `[auth.logout_check_failed]`、`[auth.logout_recovered]` 和 `[auth.canvas_reopen_failed]`。在测试团队验收时，可退出登录，确认待命页重新登录且共享 Canvas 重开。 |
| 风格初始化失败 | 检查当前团队可用风格和日志中的候选项。共享 Canvas 的歧义用 `DRAMART_VISUAL_PROMPT_ID` 处理，再按需传任务级风格。 |
| 本地记录成功，客户端打不开媒体 | 对照 `result.data`、`video_url`、`image_url` 或 `result.cdn_url`。用调用方所在网络检查该地址的访问权限和有效性。服务保存的是上游链接。 |
| 素材下载、注册或上传失败 | 核对运行机对素材的访问权限、URL 有效性、媒体大小及上游业务错误。项目视频还要看分镜的上传保存确认。 |
| 项目视频一直排队 | 查看 `queue_position`、`[task.start]`、`[task.started]` 和上一任务的子进程错误。确认有无准备超时或退出未确认。确认旧子进程和对应分镜状态后，按重启流程处理。 |
| Chrome 正好在到期时未轮换 | 先查活动任务是否仍在等待或执行。24 小时是轮换触发点，服务在空闲时执行轮换。 |

故障记录保留错误文本、任务 ID、任务类型和相关上游 ID。外发前移除凭据、私有素材 URL、请求内容及本地路径中的敏感信息。

## 重启、维护与交接

1. 记录当前版本、工作目录和配置。先暂停新任务流量，检查 `running` 及日志，尽量等待任务结束。服务没有专门的停止接单或优雅排空 HTTP 接口。
2. 通过实际使用的终端或进程管理器停止实例。维护现有数据前按环境约定备份 `requests`、`running`、`results`，并一起保留对应关系。Chrome 档案和凭据按部署环境的账号交接方式处理。
3. 需要修复损坏记录时，先留存副本，对照任务 ID、运行状态和上游项目，确定影响。不要因为查询返回 `processing` 就批量删除运行文件或重复提交。
4. 用相同工作副本和已核对的配置启动。检查服务监听、[启动恢复行为](runtime-and-data.md#服务重启如何处理未完成任务)与关键任务结果。遇到中断的任务，先在上游确认是否已产生结果，再决定是否重提。
5. 检查请求、结果和临时目录占用。清理请求文件前确认它们没有被持久化排队任务引用。真实保留期和清理频率按部署环境确认。

## 上线前需要环境负责人确认

- 部署主机、运行账号、图形桌面或会话、启动和重启方式，以及端口、反向代理、TLS 和访问控制。
- Dramart 测试与生产团队、可用模型、风格 ID、账号权限、计费与用量安排，以及出站域名或代理要求。
- 进程和任务监控、日志归集、告警值班、保留期、备份位置与恢复目标，以及媒体 URL 的可访问期限。
- 是否运行多实例及如何隔离工作副本、任务目录和 Chrome 档案。目前仓库没有共享任务状态或跨实例协调。
